# Design Document: Hammam Kernel

## Overview

Hammam Kernel — монолитное ядро операционной системы PINDOS для архитектуры x86/x86-64, разрабатываемое с нуля. Ядро реализует классическую монолитную архитектуру: все подсистемы исполняются в едином адресном пространстве ring 0 и взаимодействуют через прямые вызовы функций, что обеспечивает минимальные накладные расходы на межкомпонентное взаимодействие.

### Ключевые характеристики

- **Архитектура**: x86 (IA-32) и x86-64 (AMD64/Intel 64) в едином образе
- **Модель ядра**: монолитная с поддержкой загружаемых модулей (ring 0)
- **Совместимость**: POSIX.1-2017, нативный запуск GNU-программ без перекомпиляции
- **Многозадачность**: вытесняющая, SMP до 256 ядер
- **Безопасность**: KPTI, ASLR, NX, stack canaries, seccomp, capabilities

### Цели дизайна

1. Минимальная латентность системных вызовов (≤ 100 нс для `getpid`/`gettimeofday`)
2. Полная POSIX.1-2017 совместимость для GNU Coreutils, Bash, GCC, glibc
3. Надёжная изоляция процессов и защита ядра
4. Модульность через загружаемые модули ядра без перезагрузки
5. Загрузка системы ≤ 5 секунд на SSD-оборудовании

### Механизм системных вызовов

На x86-64 используется инструкция `SYSCALL`/`SYSRET` (AMD) и `SYSENTER`/`SYSEXIT` (Intel):

```
Пользовательское пространство (ring 3):
  rax = номер системного вызова
  rdi, rsi, rdx, r10, r8, r9 = аргументы (до 6)
  SYSCALL → переход в ring 0

Ядро (ring 0):
  1. Сохранение контекста пользователя (rsp, rip, rflags)
  2. Переключение на стек ядра (per-CPU kernel stack)
  3. Поиск обработчика в syscall_table[rax]
  4. Проверка аргументов (валидация указателей, прав доступа)
  5. Выполнение обработчика
  6. Возврат результата в rax
  SYSRET → возврат в ring 3
```

## Components and Interfaces

### 1. Scheduler (Планировщик задач)

**Алгоритм**: Completely Fair Scheduler (CFS) для SCHED_OTHER + очереди реального времени для SCHED_FIFO/SCHED_RR.

**Структура планировщика**:
```
┌─────────────────────────────────────────────────────────────────┐
│                        Scheduler                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  Per-CPU Run Queue                                       │   │
│  │  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐  │   │
│  │  │  RT Queue    │  │  CFS RB-Tree │  │  Idle Task   │  │   │
│  │  │ (FIFO/RR)    │  │ (SCHED_OTHER)│  │              │  │   │
│  │  └──────────────┘  └──────────────┘  └──────────────┘  │   │
│  └─────────────────────────────────────────────────────────┘   │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  Load Balancer (SMP, дисбаланс ≤ 15%)                   │   │
│  └─────────────────────────────────────────────────────────┘   │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │  Timer Subsystem (квант 1–20 мс, тик ≤ 4 мс)            │   │
```

## Data Models

### Структуры данных ядра

#### task_struct — дескриптор процесса/потока
```c
struct task_struct {
    /* Идентификация */
    pid_t           pid;            /* ID процесса */
    pid_t           tgid;           /* ID группы потоков (= pid для главного) */
    pid_t           ppid;           /* ID родительского процесса */
    uid_t           uid, euid, suid;
    gid_t           gid, egid, sgid;

    /* Состояние */
    volatile long   state;          /* TASK_RUNNING, TASK_INTERRUPTIBLE, ... */
    int             exit_code;
    int             exit_signal;

    /* Планировщик */
    int             policy;         /* SCHED_OTHER / SCHED_FIFO / SCHED_RR */
    int             static_prio;    /* статический приоритет [0..139] */
```

## Correctness Properties


*Свойство — это характеристика или поведение, которое должно выполняться при всех допустимых исполнениях системы. Свойства служат мостом между читаемыми человеком спецификациями и машинно-верифицируемыми гарантиями корректности.*

### Property 1: Round-trip загрузки и выгрузки модуля ядра

*Для любого* корректного модуля ядра: после его загрузки и последующей выгрузки количество занятых ресурсов ядра (страниц памяти, файловых дескрипторов, IRQ-обработчиков) должно быть идентично значению до загрузки модуля.

**Validates: Requirements 1.3, 6.2**

---

### Property 2: Корректность кодов ошибок при открытии файла

*Для любого* пути к файлу: если файл не существует — VFS возвращает ENOENT; если у процесса нет прав доступа — возвращает EACCES; если достигнут лимит файловых дескрипторов процесса — возвращает EMFILE; если файл существует и доступен — возвращает валидный дескриптор.

**Validates: Requirements 5.6**

---

### Property 3: Инвариант изоляции адресных пространств процессов

*Для любых* двух одновременно существующих процессов P1 и P2: попытка процесса P1 напрямую прочитать или записать виртуальный адрес из адресного пространства P2 (без использования явных IPC-механизмов) должна быть отклонена ядром с доставкой сигнала SIGSEGV процессу P1, не затрагивая P2.

**Validates: Requirements 9.1, 2.8**

---

### Property 4: Инвариант Copy-on-Write при fork()

*Для любого* процесса-родителя с произвольным набором страниц памяти: сразу после вызова `fork()` физические адреса страниц дочернего процесса совпадают с физическими адресами родителя (страницы разделяются); после первой записи дочернего процесса в любую из этих страниц физический адрес страницы в дочернем процессе должен отличаться от адреса в родительском (страница скопирована).

**Validates: Requirements 4.6**

---

### Property 5: Энтропия ASLR

*Для любых* N ≥ 100 последовательных запусков одного и того же исполняемого файла: множество базовых адресов стека, кучи и mmap-региона должно содержать не менее 2^28 теоретически возможных значений, а наблюдаемое распределение должно быть статистически совместимо с равномерным распределением на этом множестве.

**Validates: Requirements 4.10**

---

### Property 6: Инвариант кванта времени планировщика

*Для любого* потока с любой политикой планирования (SCHED_OTHER, SCHED_FIFO, SCHED_RR): измеренный квант процессорного времени, выделенный потоку за один раз, должен находиться в диапазоне [1 мс, 20 мс].

**Validates: Requirements 3.1**

---

### Property 7: Инвариант вытеснения по приоритету

*Для любой* пары потоков (высокий приоритет H, низкий приоритет L), где L исполняется на CPU, а H переходит в состояние RUNNABLE: время от момента готовности H до момента его фактического исполнения не должно превышать 4 мс.

**Validates: Requirements 3.3**

---

### Property 8: Инвариант балансировки нагрузки SMP

*Для любого* набора из N потоков, распределённых по K процессорным ядрам (K ≥ 2): отношение максимальной нагрузки на ядро к минимальной нагрузке на ядро не должно превышать 1.15 (дисбаланс ≤ 15%).

**Validates: Requirements 3.5**

---

### Property 9: Anti-starvation инвариант планировщика

*Для любого* потока с низким приоритетом, ожидающего исполнения более 500 мс: планировщик должен повысить его динамический приоритет на величину от 1 до 10 уровней включительно, и после получения кванта времени приоритет должен быть возвращён к исходному значению.

**Validates: Requirements 3.8**

---

### Property 10: Инвариант глубины символических ссылок

*Для любой* цепочки символических ссылок длиной N: если N ≤ 40 — VFS должна успешно разрешить ссылку; если N > 40 — VFS должна вернуть ошибку ELOOP и не разрешать ссылку.

**Validates: Requirements 5.4**

---

### Property 11: Инвариант освобождения ресурсов при завершении процесса

*Для любого* процесса с произвольным набором ресурсов (страницы памяти, файловые дескрипторы, блокировки, IPC-объекты): после завершения процесса суммарное количество занятых системных ресурсов должно вернуться к значению, которое было до создания этого процесса.

**Validates: Requirements 2.2**

---

### Property 12: Инвариант seccomp-фильтрации

*Для любого* seccomp-фильтра F и любого системного вызова S, заблокированного фильтром F: попытка процесса с активным фильтром F выполнить системный вызов S должна приводить к доставке сигнала SIGSYS этому процессу, а не к выполнению системного вызова.

**Validates: Requirements 9.5**

---

### Property 13: Инвариант кольцевого буфера журнала

*Для любого* количества записей N, записанных в журнал ядра: если N превышает ёмкость буфера C, то в буфере должны присутствовать ровно последние C записей (наиболее новые), а более старые записи должны быть перезаписаны. Порядок записей в буфере должен соответствовать порядку их записи.

**Validates: Requirements 11.1**

---

### Property 14: Инвариант длины сообщений журнала

*Для любого* сообщения журнала длиной N байт: если N ≤ 1024 — сообщение записывается полностью; если N > 1024 — сообщение усекается до 1024 байт. Уровень важности сообщения должен сохраняться независимо от его длины.

**Validates: Requirements 11.3**

---

### Property 15: Инвариант доставки сигналов

*Для любого* процесса P и любого валидного сигнала S: если сигнал S отправлен процессу P, то он должен быть доставлен в соответствии с POSIX-семантикой (обработчик вызван, действие по умолчанию выполнено, или сигнал заблокирован — в зависимости от маски сигналов процесса). Доставка сигнала одному процессу не должна влиять на состояние других процессов.

**Validates: Requirements 2.7**

## Error Handling

### Стратегия обработки ошибок

Hammam Kernel использует трёхуровневую стратегию обработки ошибок:

#### Уровень 1: Восстанавливаемые ошибки (OOPS)
Ошибки, не повреждающие критические структуры данных ядра:
- Ошибка в драйвере устройства → выгрузка модуля, запись в журнал, продолжение работы
- Ошибка в обработчике прерывания → отключение IRQ, запись диагностики
- Ошибка в файловой системе → размонтирование FS, возврат EIO пользователю

```c
/* Макрос для обработки OOPS */
#define KERNEL_OOPS(fmt, ...) do {          \
    oops("OOPS: " fmt, ##__VA_ARGS__);      \
    dump_stack();                            \
    dump_registers();                        \
} while(0)
```

#### Уровень 2: Критические ошибки (Kernel Panic)
Ошибки, делающие продолжение работы невозможным:
- Повреждение страничных таблиц ядра
- Двойное исключение (#DF)
- Переполнение стека ядра
- Нарушение инварианта критической структуры данных

```c
/* Kernel panic: вывод диагностики и остановка */
void panic(const char *fmt, ...) {
    /* 1. Отключить прерывания на всех CPU */
    /* 2. Вывести сообщение паники */
    /* 3. Дамп стека вызовов */
    /* 4. Дамп регистров */
    /* 5. Остановить систему (HLT) */
}
```

#### Уровень 3: Ошибки пользовательского пространства
Все ошибки, возникающие при обработке системных вызовов, возвращаются как отрицательные коды errno:

| Ситуация | Код ошибки |
|----------|-----------|
| Файл не найден | ENOENT (-2) |
| Нет прав доступа | EACCES (-13) |
| Нет памяти | ENOMEM (-12) |
| Ресурсы исчерпаны | EAGAIN (-11) |
| Неверный аргумент | EINVAL (-22) |
| Неверный ELF | ENOEXEC (-8) |
| Ошибка ввода-вывода | EIO (-5) |
| Слишком глубокая цепочка ссылок | ELOOP (-40) |
| Лимит файловых дескрипторов | EMFILE (-24) |
| Операция не реализована | ENOSYS (-38) |
| Нет прав суперпользователя | EPERM (-1) |
| Прерван сигналом | EINTR (-4) |

### Обработка исключений процессора (x86)

| Исключение | Вектор | Обработка |
|-----------|--------|-----------|
| #DE Division Error | 0 | SIGFPE → процесс |
| #DB Debug | 1 | ptrace/отладчик |
| #NMI Non-Maskable Interrupt | 2 | аппаратная ошибка → panic |
| #BP Breakpoint | 3 | ptrace/отладчик |
| #OF Overflow | 4 | SIGFPE → процесс |
| #BR Bound Range | 5 | SIGSEGV → процесс |
| #UD Invalid Opcode | 6 | SIGILL → процесс |
| #NM Device Not Available | 7 | FPU lazy save/restore |
| #DF Double Fault | 8 | kernel panic |
| #TS Invalid TSS | 10 | kernel panic |
| #NP Segment Not Present | 11 | SIGSEGV → процесс |
| #SS Stack Fault | 12 | SIGSEGV → процесс |
| #GP General Protection | 13 | SIGSEGV/SIGBUS → процесс или panic |
| #PF Page Fault | 14 | VMM page fault handler |

## Testing Strategy

### Подход к тестированию

Hammam Kernel использует двойной подход к тестированию:
1. **Unit-тесты** — конкретные примеры, граничные условия, коды ошибок
2. **Property-based тесты** — универсальные свойства для широкого диапазона входных данных

### Библиотека property-based тестирования

Для ядра на C используется **[Theft](https://github.com/silentbicycle/theft)** — библиотека PBT для C, не требующая внешних зависимостей. Каждый property-тест выполняется минимум **100 итераций**.

Формат тега для каждого теста:
```c
/* Feature: hammam-kernel, Property N: <текст свойства> */
```

### Unit-тесты

**Планировщик (Scheduler)**:
- Тест создания задачи с каждой политикой (SCHED_OTHER, SCHED_FIFO, SCHED_RR)
- Тест вытеснения: задача с высоким приоритетом вытесняет низкоприоритетную
- Тест idle: при отсутствии задач CPU переходит в HLT
- Тест SMP: задачи распределяются по всем доступным ядрам

**VMM**:
- Тест выделения и освобождения страниц (buddy allocator)
- Тест mmap/munmap/mprotect с корректными и некорректными аргументами
- Тест page fault для присутствующих и отсутствующих страниц
- Тест ENOMEM при исчерпании памяти

**VFS**:
- Тест каждой операции (open/read/write/close/stat/unlink/rename/mkdir/rmdir)
- Тест монтирования/размонтирования ext4, FAT32, tmpfs
- Тест procfs: чтение /proc/self, /proc/cpuinfo, /proc/meminfo
- Тест sysfs: чтение /sys/bus/, /sys/class/

**Network_Stack**:
- Тест TCP-соединения через loopback
- Тест UDP-датаграмм через loopback
- Тест AF_UNIX сокетов
- Тест epoll с несколькими дескрипторами

**Security_Module**:
- Тест KPTI: попытка доступа к памяти ядра из ring 3 → #GP
- Тест capabilities: операция без CAP_SYS_ADMIN → EPERM
- Тест NX: попытка исполнения данных → SIGSEGV

### Property-based тесты

```c
/* Feature: hammam-kernel, Property 1: round-trip загрузки/выгрузки модуля */
THEFT_TEST(module_load_unload_roundtrip) {
    /* Генерировать: случайный корректный модуль ядра */
    /* Действие: загрузить → выгрузить */
    /* Проверить: ресурсы ядра идентичны исходным */
}

/* Feature: hammam-kernel, Property 3: изоляция адресных пространств */
THEFT_TEST(process_memory_isolation) {
    /* Генерировать: два процесса с произвольными адресными пространствами */
    /* Действие: P1 пытается прочитать адрес из P2 */
    /* Проверить: SIGSEGV доставлен P1, P2 продолжает работу */
}

/* Feature: hammam-kernel, Property 4: CoW при fork() */
THEFT_TEST(fork_copy_on_write) {
    /* Генерировать: процесс с N страницами произвольного содержимого */
    /* Действие: fork() → запись в дочернем */
    /* Проверить: до записи физические адреса совпадают; после — расходятся */
}

/* Feature: hammam-kernel, Property 6: квант времени планировщика */
THEFT_TEST(scheduler_time_slice_range) {
    /* Генерировать: поток с случайной политикой и приоритетом */
    /* Действие: запустить, измерить квант */
    /* Проверить: квант ∈ [1 мс, 20 мс] */
}

/* Feature: hammam-kernel, Property 10: глубина символических ссылок */
THEFT_TEST(symlink_depth_limit) {
    /* Генерировать: цепочку символических ссылок длиной N */
    /* Действие: разрешить ссылку */
    /* Проверить: N ≤ 40 → успех; N > 40 → ELOOP */
}

/* Feature: hammam-kernel, Property 13: кольцевой буфер журнала */
THEFT_TEST(klog_ring_buffer_invariant) {
    /* Генерировать: N записей произвольного содержимого */
    /* Действие: записать все N записей */
    /* Проверить: доступны последние min(N, capacity) записей в правильном порядке */
}

/* Feature: hammam-kernel, Property 12: seccomp-фильтрация */
THEFT_TEST(seccomp_filter_blocks_syscall) {
    /* Генерировать: случайный seccomp-фильтр с набором заблокированных syscall */
    /* Действие: попытаться выполнить заблокированный syscall */
    /* Проверить: доставлен SIGSYS, syscall не выполнен */
}
```

- Загрузка системы до shell prompt: измерить время (≤ 5 с на SSD)
